# HELLFALL

A first-person horror demo built in **Unreal Engine 5.8** for Windows x64.

You wake in the supply closet of an executive floor after something has torn through the building. The only way out is a floor-level air duct into the break room; from there the main corridor leads past the restrooms, two offices, a collapsed hallway and a dead elevator to Reception and the CEO's office, whose full-width window looks out over a city on fire (the "money shot"). A dead security guard's pump shotgun is the only weapon. Two demons stand between you and the window.

The project is delivered through **six approval gates** (see below). Everything in the repository is text: gameplay is C++, levels are generated by Python editor scripts, tuning lives in JSON. Unreal's binary formats (`.umap`, `.uasset`) appear only as generated output under `Content/` and are tracked with Git LFS.

```
Config/                  DefaultEngine.ini, DefaultGame.ini, DefaultInput.ini, DefaultEditor.ini (text; rendering path decisions live here)
Content/                 GENERATED, never hand-edited. Maps/L_ExecutiveFloor, Maps/L_FeelGym, Greybox/Materials. Git LFS.

                         greybox_style.json (tints, lights, labels), levels.json (level registry)
Docs/                    BUILD-PLAN.md (the spec, verbatim), METRICS.md, FLOORPLAN.md, FLOORPLAN-SCHEMA.md,
                         TOOLCHAIN-SETUP.md, ASSET-MANIFEST.md, audit/ (machine + GLB audits)
Tools/                   PowerShell drivers, Python editor scripts (Tools/ue/), node validators; Tools/blender/ is created at Gate 4
SourceAssets/            Rob's supplied bundle: models/, audio/, textures/, video/, reference/. Git LFS. Never imported directly (G-1).
```

C++ classes: `AHellfallCharacter`, `UHellfallMovementComponent` (three-stance stand/crouch/crawl movement), `AHellfallPlayerController`, `AHellfallGameMode`, `AHellfallHUD` (on-screen control list), `UHellfallTuning` (game-instance subsystem that loads `Data/movement.json`).

## The gate process

| Gate | Focus | Rob evaluates |
|---|---|---|
| 0 | Project foundation and packaging pipeline (REQ-G1-001) | The `.zip` runs to a first-person view. |
| 1 | Greybox and traversal, feel gym, metrics standard | Does the space feel right to move through? |
| 2 | Blockout props and composition | Does every room read with objects at final scale? |
| 3 | Materials and lighting | Does it look like the "after" mood board? |
| 4 | Final 3D assets (through Blender) | Do the real models sit in the approved space? |
| 5 | Core gameplay (5A weapon, 5B demons) | Does the shotgun feel right? Are the demons threatening? |
| 6 | Shell, systems and ship | Menus, audio mixer, save/load, cutscenes, docs, final package. |

Every gate ships a tagged GitHub Release (`gate-N`, revisions `gate-N.1`, ...) with a packaged Windows x64 `.zip`, plus `GATE-N-NOTES.md` in the repo root. Rob answers APPROVED or a feedback list; approved scope is frozen. Full text: [Docs/BUILD-PLAN.md](Docs/BUILD-PLAN.md).

## Controls

Binds come from `Data/movement.json` (`binds`) and are shown on screen by the HUD. Change the JSON, rebuild, no code edit.

| Action | Key | Notes |
|---|---|---|
| Move | W / A / S / D | Relative to camera yaw; diagonal speed equals forward speed |
| Look | Mouse | Pitch clamped to +/-89 degrees; focus loss releases the mouse without a camera snap on return |
| Jump | Space | Grounded only, 0.10 s coyote time; suppressed while crouched or crawling |
| Crouch (toggle) | Left Ctrl | Capsule 116 cm |
| Crawl (toggle) | C | Capsule 64 cm; the only stance that fits the air duct |
| Sprint (hold) | Left Shift | 600 cm/s (walk is 400) |
| Interact | E | Gate 5 (shotgun pickup, locked door refusal) |
| Pause | Esc | Gate 6 pause menu; until then releases the mouse |
| Feel gym | F1 | Switches between `L_ExecutiveFloor` and `L_FeelGym`; `Launch-FeelGym.cmd` in the packaged build starts the gym directly |

## Building and running

All scripts are run from the repository root in PowerShell. Each one prints what it is about to do and where the engine was found, tried in this order: `$env:UE_ROOT`, the default `C:\Program Files\Epic Games\UE_5.8` (accepted only when its `Engine\Build\Build.version` matches), then the Launcher's HKLM registry key, then HKCU-registered source builds.

```powershell
.\Tools\ue\run_editor_script.ps1 -Script build_greybox.py -NoCode   # generates /Game/Maps/L_ExecutiveFloor from Data/floorplan.json (works today, no C++ needed)
.\Tools\ue\run_editor_script.ps1 -Script build_feel_gym.py -NoCode  # generates /Game/Maps/L_FeelGym from Data/metrics.json
.\Tools\generate_project_files.ps1                      # UnrealBuildTool -projectfiles -> Hellfall.sln           (needs VS Build Tools)
.\Tools\build_editor.ps1                                # Build HellfallEditor Win64 Development                  (needs VS Build Tools)
.\Tools\package.ps1 -Tag gate-0                         # UAT BuildCookRun -> Windows x64 Development .zip (Data/ staged alongside)
.\Tools\release.ps1 -Tag gate-0                         # gh release create gate-0 with the .zip and GATE-0-NOTES.md
```

**Map generation does not need the compiled C++ module.** `-NoCode` writes a temporary `HellfallNoCode.uproject` (the same JSON as `Hellfall.uproject` with the `Modules` array removed), runs `UnrealEditor-Cmd.exe <twin> -run=pythonscript -script=<abs .py> -stdout -FullStdOutLogOutput -unattended -nosplash -nopause -NoLiveCoding`, and deletes the twin afterwards. That is how both maps were first generated on 2026-09-06 (249 and 171 actors, 0 errors, 0 warnings; [BUILD.md](BUILD.md) 1.1). Once `Binaries\Win64\UnrealEditor-Hellfall.dll` exists the switch is unnecessary and the output is expected to be identical. The twin is git-ignored and must never be committed.

Without the engine you can still exercise everything that does not need it:

```powershell
.\Tools\test_dry_run.ps1                                                          # Python generators in manifest mode (no engine) + both validators, 7 steps
node .\Tools\validate_floorplan.mjs .\Data\floorplan.json                          # schema, required rooms, fixed adjacency, metrics rules
node .\Tools\check_manifest.mjs .\Saved\Manifests\L_ExecutiveFloor.manifest.json  # overlaps, boundary, money shot on the dry-run manifest (run test_dry_run.ps1 first)
```

Both validators take the file to check as their first argument and print usage (exit 2) without it.

To play a packaged build: unzip, run `Hellfall.exe` (or `Launch-FeelGym.cmd` for the calibration level). Development builds show the on-screen control list at all times.
