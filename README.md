# HELLFALL

A first-person horror demo built in **Unreal Engine 5.8** for Windows x64.

You wake in the supply closet of an executive floor after something has torn through the building. The only way out is a floor-level air duct into the break room; from there the main corridor leads past the restrooms, two offices, a collapsed hallway and a dead elevator to Reception and the CEO's office, whose full-width window looks out over a city on fire (the "money shot"). A dead security guard's pump shotgun is the only weapon. Two demons stand between you and the window.

The project is delivered through **six approval gates** (see below). Everything in the repository is text: gameplay is C++, levels are generated by Python editor scripts, tuning lives in JSON. Unreal's binary formats (`.umap`, `.uasset`) appear only as generated output under `Content/` and are tracked with Git LFS.

## The gate process

| Gate | Focus | Rob evaluates |
|---|---|---|
| 0 | Project foundation and packaging pipeline (REQ-G1-001) | The `.zip` runs to a first-person view. |
| 1 | Greybox and traversal, feel gym, metrics standard | Does the space feel right to move through? |
| 2 | Blockout props and composition | Does every room read with objects at final scale? |
| 3 | Materials and lighting | Does it look like the "after" mood board? |
| 4 | Final 3D assets (through Blender) | Do the real models sit in the approved space? |
| 5 | Core gameplay (5A weapon, 5B demons) | Does the shotgun feel right? Are the demons threatening? |
| 6 | Shell, systems and ship | Menus, audio mixer, save/load, cutscenes, docs, final package. |

Every gate ships a tagged GitHub Release (`gate-N`, revisions `gate-N.1`, ...) with a packaged Windows x64 `.zip`, plus `GATE-N-NOTES.md` in the repo root. Rob answers APPROVED or a feedback list; approved scope is frozen. Full text: [Docs/BUILD-PLAN.md](Docs/BUILD-PLAN.md).

## Controls

Binds come from `Data/movement.json` (`binds`) and are shown on screen by the HUD. Change the JSON, rebuild, no code edit.

| Action | Key | Notes |
|---|---|---|
| Move | W / A / S / D | Relative to camera yaw; diagonal speed equals forward speed |
| Look | Mouse | Pitch clamped to +/-89 degrees; focus loss releases the mouse without a camera snap on return |
| Jump | Space | Grounded only, 0.10 s coyote time; suppressed while crouched or crawling |
| Crouch (toggle) | Left Ctrl | Capsule 116 cm |
| Crawl (toggle) | C | Capsule 64 cm; the only stance that fits the air duct |
| Sprint (hold) | Left Shift | 600 cm/s (walk is 400) |
| Interact | E | Gate 5 (shotgun pickup, locked door refusal) |
| Pause | Esc | Gate 6 pause menu; until then releases the mouse |
| Feel gym | F1 | Switches between `L_ExecutiveFloor` and `L_FeelGym`; `Launch-FeelGym.cmd` in the packaged build starts the gym directly |

## Building and running

All scripts are run from the repository root in PowerShell. Each one prints what it is about to do and where the engine was found, tried in this order: `$env:UE_ROOT`, the default `C:\Program Files\Epic Games\UE_5.8` (accepted only when its `Engine\Build\Build.version` matches), then the Launcher's HKLM registry key, then HKCU-registered source builds.

```powershell
.\Tools\generate_project_files.ps1                      # UnrealBuildTool -projectfiles -> Hellfall.slnx          (ran 2026-09-06: 18.5 s)
.\Tools\build_editor.ps1                                # Build HellfallEditor Win64 Development                  (ran 2026-09-06: Result: Succeeded)
.\Tools\ue\run_editor_script.ps1 -Script build_greybox.py   # generates /Game/Maps/L_ExecutiveFloor from Data/floorplan.json + Data/blockout.json when present (999 actors in the dry run: 590 greybox + 409 blockout; --no-blockout = the approved 590; add -NoCode to run without the compiled module)
.\Tools\ue\run_editor_script.ps1 -Script build_feel_gym.py  # generates /Game/Maps/L_FeelGym from Data/metrics.json (222 actors, enclosed hall)
.\Tools\package.ps1 -Tag gate-2                         # UAT BuildCookRun -> Builds\Hellfall-gate-2-Win64-Development.zip, Data/ staged alongside (gate-1 ran in 122 s / 327.6 MB)
.\Tools\release.ps1 -Tag gate-2                         # gh release create gate-2 with the .zip and GATE-2-NOTES.md
```

The floor itself is generated one step earlier: `node Docs\candidates\legal_lead.build.mjs Data\floorplan.json` rewrites `Data/floorplan.json` from the room table and opening calls in that script (self-checks refuse a broken plan). Edit the script, not the JSON, or the change is lost on the next generate ([Docs/FLOORPLAN.md](Docs/FLOORPLAN.md) section 12). The Gate 2 blockout layer works the same way: `node Docs\blockout\blockout.build.mjs` rewrites `Data/blockout.json` from the placement table in that script (it refuses to write while any placement rule fails), `node Docs\blockout\blockout.tables.mjs` regenerates the tables in [Docs/blockout/BLOCKOUT.md](Docs/blockout/BLOCKOUT.md) (`--manifest` rewrites the "Blockout (Gate 2)" column of `Docs/ASSET-MANIFEST.md`), and `build_greybox.py` picks the file up automatically. The asset sizes it uses come from the headless Blender audit: `"C:\Program Files\Blender Foundation\Blender 5.2\blender.exe" --background --factory-startup --python Tools\blender\audit_glb.py -- Docs\audit\blender_audit_2026-09-07.json` ([Tools/blender/README.md](Tools/blender/README.md)).

Review tooling (needs a packaged Development build; not gameplay):

```powershell
Builds\gate-2\Windows\Hellfall.exe /Game/Maps/L_ExecutiveFloor?spawn=4100,-2500,0,-30   # start at Unreal X,Y,Z (cm) facing Yaw (deg) instead of the PlayerStart - here the CEO office: desk, couch set, dead CEO, Demon #2 behind the wall
.\Tools\screenshot_sweep.ps1 -Tag gate-2 [-Only 1]     # one launch per viewpoint in Data\review_shots.json (41: 34 floor incl. 10 prop-focused, 7 gym), last -DumpMovie frame kept under Saved\ReviewShots\gate-2\<id>.png
.\Tools\contact_sheet.ps1 -Tag gate-2                  # tiles those frames per map with id + note captions -> Saved\ReviewShots\gate-2\sheet_<map>.jpg
```

`review_shots.json` positions are plan space (photo x right, y down toward the window); the sweep converts them with `X = plan.y`, `Y = -plan.x`, `yaw = plan yaw - 90`. The root `Hellfall.exe` in the staged tree is a bootstrapper that starts `Hellfall\Binaries\Win64\Hellfall.exe` and exits, so the sweep launches the inner binary directly.

**Map generation does not need the compiled C++ module.** `-NoCode` writes a temporary `HellfallNoCode.uproject` (the same JSON as `Hellfall.uproject` with the `Modules` array removed), runs `UnrealEditor-Cmd.exe <twin> -run=pythonscript -script=<abs .py> -stdout -FullStdOutLogOutput -unattended -nosplash -nopause -NoLiveCoding`, and deletes the twin afterwards. That is how both maps were first generated on 2026-09-06 (249 and 171 actors, 0 errors, 0 warnings; [BUILD.md](BUILD.md) 1.1). `Binaries\Win64\UnrealEditor-Hellfall.dll` exists since the 2026-09-06 compile, so the switch is no longer needed; identical output is expected but has not been byte-compared ([GATE-0-NOTES.md](GATE-0-NOTES.md) section 6). The twin is git-ignored and must never be committed.

Without the engine you can still exercise everything that does not need it:

```powershell
.\Tools\test_dry_run.ps1                                                          # Python generators in manifest mode (no engine) + all validators + scenes and blockout smoke tests, 14 steps (~25 s)
node .\Tools\validate_floorplan.mjs .\Data\floorplan.json                          # schema, required rooms, fixed adjacency, metrics rules, scenes; PASS line carries the exploration estimate (~10.8 min), critical-path length and junction count
node .\Tools\validate_blockout.mjs .\Data\blockout.json                            # Gate 2: schema + asset slots vs the Blender audit + placement rules (walls, overlaps, 76 swing zones, lanes, discs, scene rects, sightline strip, corridor clear widths, demon routes); PASS / FAIL
node .\Tools\check_manifest.mjs .\Saved\Manifests\L_ExecutiveFloor.manifest.json  # overlaps, boundary, enclosure (every slab walled + roofed), money shot on the dry-run manifest (run test_dry_run.ps1 first)
```

All three validators take the file to check as their first argument and print usage (exit 2) without it.

To play a packaged build: download the `.zip` from the gate's Release (gate-2: https://github.com/RobleusCaesar/hellfall/releases/tag/gate-2, `Hellfall-gate-2-Win64-Development.zip`, 327.9 MB (343,807,217 bytes); gate-1: https://github.com/RobleusCaesar/hellfall/releases/tag/gate-1, 327.6 MB (343,510,411 bytes); gate-0: https://github.com/RobleusCaesar/hellfall/releases/tag/gate-0, 327.1 MB), unzip anywhere, run `Hellfall.exe` (or `Launch-FeelGym.cmd` for the calibration level; F1 in game toggles between the two maps). Nothing installs. `BUILD-INFO.txt` next to the executable records the engine version, configuration and git revision; the tuning JSON is in `Hellfall\Data\` and can be edited in place. Development builds show the on-screen control list at all times.
