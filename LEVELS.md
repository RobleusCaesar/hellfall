# LEVELS.md - level authoring guide

**Status: stub.** This is the Gate 6 deliverable (REQ-G6-006). It is completed when the level template, level manager and registry exist and a second level has actually been added by following this document. Until then it records only what already exists so the file paths below are real.

## Purpose

Walk a new developer from an empty map to a registered, playable level using only the files in this repository: no editor-authored `.umap` edits, no Blueprints. Levels are generated by Python editor scripts from JSON under `Data/`, so adding a level is a data change plus a generator run.

## What exists now (Gate 0/1/2)

| Piece | Path | Role |
|---|---|---|
| Level registry | `Data/levels.json` | `executive_floor -> /Game/Maps/L_ExecutiveFloor` (order 10), `feel_gym -> /Game/Maps/L_FeelGym` (order 900, hidden). Each entry carries `id`, `display_name`, `map`, `order` and optional `hidden`. Read by `UHellfallTuning` to resolve a level id to a map path; the F1 toggle uses it. |
| Main level source | `Data/floorplan.json` (+ `Data/metrics.json`, `Data/greybox_style.json`) | Rooms, openings, ducts, blockers, markers, checkpoints, encounters, scenes, money shot, critical path. Schema: `Docs/FLOORPLAN-SCHEMA.md`. Since gate-1 the JSON is itself generated: `node Docs/candidates/legal_lead.build.mjs Data/floorplan.json` (edit the script, then regenerate). Frozen since Gate 1 approval (2026-09-07). |
| Blockout layer (Gate 2) | `Data/blockout.json` (GENERATED by `node Docs/blockout/blockout.build.mjs`; schema: `Docs/FLOORPLAN-SCHEMA.md` "Blockout data"; rationale: `Docs/blockout/BLOCKOUT.md`) | A second, optional data file the main level generator picks up automatically when the plan is `Data/floorplan.json` (`--blockout <file>` / `--no-blockout` override). Places, INSIDE the approved rooms, 192 props (17 audited asset slots + a generic law-firm kit), 4 characters, 1 pickup with its halo, 2 demon cylinders with footprint slabs, the 2 encounter trigger volumes, the dwell volume and the backdrop plane, all as labelled boxes in `Blockout/*` outliner folders; asset sizes come from the Blender audit `Docs/audit/blender_audit_2026-09-07.json`. Regenerated 2026-09-07. Without the file the build is the approved Gate 1 greybox byte for byte. |
| Main level generator | `Tools/ue/build_greybox.py` | Reads the JSON above and emits `/Game/Maps/L_ExecutiveFloor` through `Tools/ue/hf_common.py` (UnrealEmitter inside the editor, ManifestEmitter without it). Geometry maths is in `Tools/ue/hf_geometry.py` (pure Python, testable without the engine). |
| Feel gym generator | `Tools/ue/build_feel_gym.py` | Reads `Data/metrics.json` (`feel_gym` block) and emits `/Game/Maps/L_FeelGym`. |
| Driver | `Tools/ue/run_editor_script.ps1 -Script <name>.py` | Runs a generator headless with `UnrealEditor-Cmd.exe -run=pythonscript`. `-NoCode` runs it against a temporary code-free twin project (`HellfallNoCode.uproject`, git-ignored, deleted afterwards) so maps can be generated before the C++ module is compiled. |
| Validators | `Tools/validate_floorplan.mjs`, `Tools/validate_blockout.mjs`, `Tools/check_manifest.mjs` | Run before any generation; fail loudly on schema, adjacency or metric violations (`validate_floorplan`), on blockout placement-rule violations - walls, overlaps, swing zones, lanes, discs, scene rects, the money-shot strip, corridor clear widths, demon routes (`validate_blockout`, Gate 2) - and on the built manifest's overlaps, enclosure, room containment and money shot (`check_manifest`). `Tools/test_dry_run.ps1` runs all of them without the engine (14 steps). |
| Generated output | `Content/Maps/L_ExecutiveFloor.umap`, `Content/Maps/L_FeelGym.umap`, `Content/Greybox/Materials/M_GB_*.uasset` (42 tints: 29 greybox, 11 of them textured, + 13 blockout / volume / backdrop tints since Gate 2) | Output only (Git LFS), never hand-edited. **Regenerated 2026-09-07 for gate-2:** `L_ExecutiveFloor` = the approved 37-room law-firm floor (590 greybox actors: 129 walls, 41 headers, 37 floor + 37 ceiling slabs, 59 fill lights, 31 markers - unchanged since Gate 1 approval) **plus the blockout layer** (409 actors in `Blockout/*`: 192 props, 4 characters, 1 pickup + halo, 2 demon cylinders + 2 footprint slabs, 2 trigger volumes, 1 dwell volume, 1 backdrop, 203 labels) = **999 actors in the dry-run manifest**, 513 collision boxes, 0 overlaps; `L_ExecutiveFloor.umap` on disk 1,744,821 bytes. `L_FeelGym` = the enclosed hall, **222 actors**, unchanged (regenerated in the same run, 394,249 bytes). The floor's design lives in `Docs/candidates/legal_lead.build.mjs` (-> `Data/candidates/legal_lead.json` = `Data/floorplan.json`), the blockout's in `Docs/blockout/blockout.build.mjs` (-> `Data/blockout.json`); the gate-1 maps (590 / 222 actors) are reproduced with `--no-blockout`, the gate-0 maps (249 / 171 actors, committed in `12faf06`) from `Data/candidates/floorplan_gate0.json`. Shipped in the gate-2 package (`Hellfall-gate-2-Win64-Development.zip`, `BUILD.md` 1.5; gate-1: `BUILD.md` 1.4). Re-committed at gate tags only. |
