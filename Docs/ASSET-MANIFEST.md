# Asset manifest - `SourceAssets/`

Every file Rob supplied, grouped by folder, with the Unreal name it will receive when (and if) it is imported. This is the complete list; the shorter working-set table in `BUILD.md` section 5 covers only the 17 meshes with their audited real-world targets. **REQ-G2-001 was completed on 2026-09-07**: every mesh was opened headlessly in Blender 5.2.1 (`Tools/blender/audit_glb.py`), measured in rest pose, cross-checked against the node header parser and given its ruling - `Docs/audit/blender_audit_2026-09-07.md` (+ `.json`). The G2-001 table below is the audited working set; the per-file mesh rows carry the audited counts and rest sizes. Audio, textures, video and reference are still described from the files themselves.

## Provenance

- The models were generated with **Meshy.ai** under Rob's account from the concept images in `reference/`; audio, video, UI images and mood boards were supplied by Rob (source tools not recorded - Rob to confirm if any third-party licence applies).
- This tree is **already the de-duplicated working set** produced by Rob's earlier Godot attempt (`RobleusCaesar/hellfallGPT`): one candidate per slot was chosen there, ` - Copy` duplicates were dropped, `Meshy_AI_*` prefixes and the `deamon` misspelling were renamed, and the 17 GLBs were decimated to 3.8k-23.8k triangles with glTF-Transform 4.5.0. The raw 2.8 GB Meshy bundle is **not on this machine**, so the rejected alternatives (`shotgun2`, `ceo_dead2`, the third demon) cannot be re-inspected. If Rob wants them reconsidered at Gate 2 he must supply the raw bundle.
- Consequence for REQ-G2-001 acceptance 2: no file here contains ` - Copy`, `Meshy_AI_` or `deamon` (verified by listing on 2026-09-05).

## Rules

1. **G-1: nothing from Meshy enters the engine without passing through Blender.** No `.glb` in this tree is imported directly. At Gate 4 each mesh goes through `Tools/blender/` (import -> real-world scale in cm -> decimate to class budget -> pivot -> apply transforms -> `UCX_` collision -> FBX) and only the FBX is imported, by script.
2. **Scale is wrong in every GLB.** The Godot pipeline normalised each static model so its longest axis is ~1.9 m regardless of which axis that is, with the bounding-box centre at the origin. The two rigged demons are the exception: **1.70 m tall with feet at z = 0** (the earlier "0.017 m, 100x too small" was the header parser applying the armature's 0.01 scale to skinned bind buffers that glTF says to ignore). Real-world targets are recorded per slot in the G2-001 table below (one driving dimension each, applied as a uniform scale so proportions hold) and set in the Gate 4 Blender pipeline.
3. **Textures beside a `.glb` are loose copies of the images embedded in it** (Meshy exports both). They are kept so Blender / Unreal can be pointed at editable files, but the embedded copy is the one that travels with the mesh. `crimson_hellfiend_texture_0_1.png` is byte-identical to `crimson_hellfiend_texture_0.png` (same size, same MD5) - **rejected - duplicate** (REQ-G2-001, 2026-09-07); removed from the working set with `git rm` in the gate-2 commit (2026-09-07); the manifest now lists 125 files. Every GLB embeds its textures at 1024 x 1024.
4. **Video:** `.ogv` (Theora/Vorbis) is not a format the Unreal Media Framework plays on Windows. Both clips are re-encoded to MP4/H.264 + AAC at Gate 6 (`ffmpeg -i intro.ogv -c:v libx264 -pix_fmt yuv420p -c:a aac intro.mp4`; ffmpeg is not yet installed). They are placeholders anyway (G-8).
5. **Audio:** WAV imports natively. MP3 import is expected to work in UE 5.8 but is not verified on this machine; if it fails the six MP3s are transcoded to WAV at Gate 3/6 and the originals stay here. `// TODO(VERIFY 5.8): MP3 import through the sound factory.`
6. **Reference images are never imported.** They exist for humans and for the floor-plan digitiser.
7. Naming on import follows Unreal convention: `SM_` static mesh, `SK_` skeletal mesh, `T_` texture (`_BC` base colour, `_MR` packed metallic/roughness, `_N` normal, `_E` emissive, `_D0` Meshy diffuse), `M_`/`MI_` materials (created at Gate 3), `SFX_`/`MUS_`/`VO_` sounds, `MS_` media sources.
8. **Blockout room of record.** The "Blockout (Gate 2)" column of the G2-001 table below names the room and `Data/blockout.json` id where each mesh's grey box stands (written by `Docs/blockout/blockout.tables.mjs --manifest`); the per-file rows repeat it in prose. `BUILD.md` 5.1, this file and `Data/blockout.json` (generated by `Docs/blockout/blockout.build.mjs`) must agree - the blockout is the authority, and a deliberate move away from the spec's room is flagged in `Docs/blockout/BLOCKOUT.md` section 7.
